## 0. 一页结论

**差异化主张（一句话）**：每一次最终写入都必须持有一张许可。许可绑定的是**被验证的那组 IEEE-754 字节**，并且只能用一次、在期限内必须执行完、撤销后只能凭撤销时刻之后的新反馈恢复。许可背后的几何结论可以在每个控制周期**按变化量增量重验**，接受与拒绝的判定与精确完整检查一致：

- 数值剖面上，在记录的浮点实验中判定逐例一致；实数域论证不等于所有浮点输入的形式证明（场景和动作量级 ≤ 1000 m，超出走完整检查）。
- 机械臂剖面上，结论可靠，且不比从头认证更保守（推论 A5）。
- 机械臂检查用连续认证而不是采样，留下的余量下一周期可以继承。

### 1.3 四个差异化能力的产品话术（每句都带适用范围）

- **D1 逐字节最终写入许可**
  - 从证书计算、许可签发到写入驱动器，绑定的都是同一组浮点数的字节。
  - 许可还绑定当时的场景内容；只能用一次，并发下也只能一次；剩余步骤必须在期限前执行完；撤销后只能用撤销时刻之后的新反馈恢复。
  - *范围*：数值剖面执行器。原生网关已有逐字节 7 维请求绑定与证据缺口检查，但没有场景内容摘要。不是功能安全认证。
- **D2 增量重验，判定不变**
  - 每个控制周期动作块被改写后，只重算发生变化的段，以及真正起约束作用的少数约束。
  - 实数域上接受或拒绝与完整检查相同；浮点实现的一致性由边界守卫和已记录实验支持。
  - *范围*：球与工作空间盒约束族。成本优势在测试的 M∈{4, 8, 16, 64, 256} 上出现，M=1 时更慢。
- **D3 连续认证 + 可继承余量**
  - 机械臂检查不依赖采样步长：整段运动给出一个认证下界。
  - 下界存成账本。下一周期按关节偏差扣减后直接继承，只重新认证扣穿的段。
  - 一次批量处理 N 个候选块。
  - *范围*：UR5e 胶囊体静态几何的运动学模型；不含动力学与跟踪误差。
- **D4 全速率逐步许可**
  - 下一张许可可以在当前许可执行时提前链入。条件是起点必须逐字节接上已提交的末端，并绑定已提交前缀的滚动摘要。
  - 因此"每步一张许可"不再需要停下来等排空。
  - 撤销时，所有链入的许可一起作废。
  - *范围*：参考模拟控制器（dt=50 ms，容量 2 或 4）上的控制周期数，不是任何机器人的墙钟延迟。

### 1.4 "更快、更准、更严"的精确定义（论文与路演统一用这一套）

| 词 | 精确定义 | 现有证据 |
|---|---|---|
| **更快** | 判定相同的前提下，每控制周期的验证墙钟（中位数与 P95）更低；根证书建立与失败回退成本计入 | D2、D3（N≥8）、D4（控制周期数） |
| **更准** | ① 与精确完整检查的判定分歧为 0；② 机械臂上不存在采样间隙漏检（连续认证，在胶囊模型内）；以"只查路点"的漏检率作对照 | D2、D3 |
| **更严** | 在固定故障集上阻断的契约故障类数；正式实验另测干净运行的误拒 | D1 |

| 逐段回退 | 任一段余量不足，整个计划完整重检 | 只重检余量不足的段 | 回退成本从 O(H·M) 降到 O(变化段数 × 局部 M) |
| 活动集账本 | 每段只存一个最小余量 | 每段存：6 个盒面 + k 个最近球的精确余量，加上其余所有球的可靠下界 `rest_lb` | 只在真正起约束的少数约束上刷新，保守性不会在它们身上累积 |
| 惰性 O(1) 继承 | — | `rest_lb − L·e ≥ ε` 且 `lb − L·e ≥ ε` 时直接扣减，不做任何距离计算（ε = `INHERIT_EPS` = 1e-9 m） | 小偏差周期只剩逐段常数开销 |
| 零偏差复用 | 按摘要整计划复用 | 两端点逐字节相同的段直接复用 | RTC 前缀冻结段、流式平移中已执行的段不再花成本 |
| 偏移对应 | 无 | 子段 k 对应父段 k+offset（流式执行丢掉已执行步、追加新步） | 流式场景也能继承 |
| 精确身份 | 规范化摘要 | `exact_hash` | 与 G1 一致 |
| 扫掠轴障碍索引 | 线性扫描全部球 | 按中心坐标沿展布最大的轴排序并二分查找；查询半径外的球余量保证 ≥ `far_cap` | M 大时减少距离计算；M 小时 v2 完整检查反而比 v1 慢（W1 351.8 vs 223.9 ms；M=1、H=16 时每周期 0.18 vs 0.044 ms），见 §5 |
| 浮点一致 | — | 精确路径用与 `geometry.full_check` 完全相同的浮点表达式与运算顺序；继承路径要求下界越过 ε；坐标绝对值超过 1000 m 时不继承 | 实数域的判定一致性成立；浮点守卫是工程边界。复核发现大尺度和索引边界反例，现已补上尺度回退、索引外扩与 1 nm 守卫；尚无覆盖全部浮点输入的形式证明 |
| 防误用 | — | 传入为别的场景构建的检查器时直接报错 | 堵住"证书盖了 A 场景的戳、却在 B 场景上算"的误用 |
| 接入 Authority | — | `to_store_certificate(CertV2)` 适配为可登记的 `Certificate`，携带逐段下界、谱系与 `plan_exact` | 可以直接签发许可（有测试）；demo/产品流水线尚未切换 |

### 2.4 链式租约流水线（D4）

代码：`src/sentinel_evc/executor_pipeline.py`。

- **提交（链入）**：运行中允许提交下一张许可，前提是：
  - `plan.knots[0]` 与已提交虚拟计划的末端逐字节相等；
  - `queue_rev` 等于上一张 + 1；
  - `committed_prefix_hash` 等于已提交虚拟计划的滚动摘要；
  - 其余提交检查一项不少：MAC、单次使用、代次、期限、精确字节、场景、新鲜反馈；
  - 调用方传入的实时上下文必须与许可上下文全字段相等。
- **派发（每步）**，依次检查：
  - 队首条目所属许可的代次、期限、剩余步完成预算、预测；
  - 环境字段；
  - 实时队列状态是否等于最近一张已提交许可的状态（复核后补上，见 §2.6 R1）；
  - 反馈是否新鲜、是否为控制器真实反馈；
  - 相对已提交虚拟计划的跟踪管。
- **撤销**：在一个临界区内推进代次、清空所有链入条目、进入 FAULT，并记 REVOKE（含 `dropped_queued_steps`）。释放锁之后才向控制器发 cancel，遵守"撤销锁不等网络"。
- **长时间运行**：
  - 已观测的虚拟节点分批裁剪，已用完的许可及时遗忘；
  - 前缀摘要改为按 IEEE-754 字节滚动计算，每张许可 O(K)；
  - 测试覆盖 600 步连续运行：状态有界，滚动摘要与全历史摘要一致。
- **Authority 配合**：`prepare(..., chained=True)` 跳过起点管检查（此时机器人还没走到链入起点），改由执行器在提交时对虚拟计划做跟踪管检查。

## 3. 理论补充（论文 §5 需新增的引理与定理）

记号沿用上一版规格书 §2.2。新增记号：

| 记号 | 含义 |
|---|---|
| `(p₀,p₁)`、`(q₀,q₁)` | 段 k 在父计划、子计划中的端点 |
| `e_k = max(‖q₀−p₀‖, ‖q₁−p₁‖)` | 端点偏差 |
| `A_k` | 活动集：6 个盒面 + k 个最近球 |
| `rest_lb_k` | 非活动球余量的下界 |
| `ε = 1e-9 m` | 继承阈值 |

### 3.1 数值剖面（v2）

**引理 V1（段余量的 1-Lipschitz 性）**
- 对同一参数化 `x(s) = (1−s)x₀ + s x₁`，有 `‖q(s) − p(s)‖ ≤ e_k`（凸组合）。
- 球余量 `m_j(seg) = min_s ‖x(s) − c_j‖ − r_j − tool − reserve` 与盒面余量都对逐点位移 1-Lipschitz，因此 `|m_j(q) − m_j(p)| ≤ e_k`，即 L = 1。

**引理 V2（远处剩余部分的可靠下界）**
- 未被 `SweepIndex.candidates(p₀,p₁,reach)` 返回的球：其中心沿索引轴到段包围区间的距离大于 `reach`，所以到段的欧氏距离也大于 `reach`。
- 取 `reach = far_cap + r_max + slack`，这些球的余量 `> far_cap`。
- 被返回但未进入活动集的球：余量 ≥ 第 k+1 近者的精确余量。
- 结论：`rest_lb = min(第 k+1 近余量, far_cap·[存在未返回的球])` 是所有非活动球余量的可靠下界。

**定理 V3（惰性继承可靠）**
- 若 `rest_lb_k − e_k ≥ ε` 且 `min_{a∈A_k} m_a − e_k ≥ ε`，则子段的所有约束余量 > 0。
- 把 `{m_a − e_k}` 与 `rest_lb_k − e_k` 存作子段账本，仍然可靠。
- 链式应用时，扣减从父的剩余量开始。定理 2 的"不回到初值"在 v2 账本的每个条目上逐项成立。

**定理 V4（实数域的逐段回退判定一致；浮点实现另行验证）**

v2 对每一段只做三件事之一：

1. 逐字节复用：余量不变；
2. 按 V1–V3 继承：继承下界 ≥ ε；
3. 精确局部检查（`check_segment`）：盒面与球余量的浮点表达式、运算顺序与 `geometry.full_check` 相同。远处球以 `far_cap > 0` 作下界，不影响符号。

只有第 3 类发现某段 `lb < 0` 才拒绝。

- 实数下：v2 接受 ⇔ 每段真实最小余量 ≥ 0 ⇔ 精确完整检查接受。
- 浮点实现：动作与场景量级超出 1000 m 时完整回退，继承最多 64 层并使用 1 nm 守卫；索引范围向外取整。该实现没有区间算术的完整舍入误差证明。“几次 ulp”的估算不足以推出任意浮点输入的定理。记录的随机与边界实验一致性见复核报告。
- 依赖失效（场景、dt、描述符、变换登记、深度上限、偏移越界、夹爪事件平移）一律回到完整检查，不影响一致性。
- 测试：`test_delta_cert_v2.py` 的随机等价测试与 ulp 级测试。试点中 5320 个判定（4320 个流式周期 + 1000 个构造案例）0 分歧。

**命题 V5（每周期成本）**
- 设本周期逐字节复用 `n_id` 段、惰性继承 `n_lazy` 段、活动集刷新 `n_act` 段、局部回退 `n_loc` 段，`c(·)` 为局部候选球数。
- 距离计算次数 = `Σ_act |A_k∩球| + Σ_loc c_k`，与 H·M 无关；墙钟另含与 H 成正比的逐段常数开销。
- 流式场景中 `n_id + n_lazy` 占绝大多数。例：H=128、M=256、jitter 0.003 的 120 个周期中，复用 360 段、继承 13,810 段、回退 1,190 段。
- 盈亏点由"每段完整检查成本 ≈ M 次距离计算"与"v2 每段固定开销"之比决定。本试点中盈亏点落在 1 < M < 4（§5 N1）。

### 3.2 机械臂剖面

**引理 A1（与配置无关的运动界）**
- 前提：关节 i 的轴经过其所在体的原点（代码已对 MJCF 断言）。
- 定义 `ρ[g,i]` = 从关节 i 所在体原点沿运动链到胶囊 g 所在体原点的平移长度之和 + 胶囊中心偏移 + 半长。
- 结论：对关节空间直线段 `q(s)`，胶囊 g 轴上任一点的位移 `≤ Σ_i ρ[g,i]·|Δq_i|`。
- 不在 g 上游的关节，`ρ[g,i] = 0`（链感知：腕部关节不会移动上臂）。

**引理 A2（区间认证）**
- 设段两端胶囊 g 的净空为 `d_a`、`d_b`，`M_g = Σ_i ρ[g,i]|Δq_i|`，则全段净空 `≥ (d_a + d_b − M_g)/2`。
- 不能认证时二分：在深度上限内采到负净空即为确定碰撞；深度耗尽则判 `unknown`，按拒绝处理。

**引理 A3（自碰撞的相对运动界）**
- 对非父子相邻的胶囊对 (a,b)（b 在 a 的下游），两者的相对位姿只受严格位于两体之间的关节影响。
- 相对位移 `≤ Σ_{i∈between} ρ[b,i]|Δq_i|`（即 `pair_rho`）。

**定理 A4（Δ-Cert-arm 继承可靠）**
- 子段与父段同参数化，端点关节偏差为 `δ_a`、`δ_b`。
- 对任意 s，`|q_c,i(s) − q_p,i(s)| ≤ max(|δ_{a,i}|, |δ_{b,i}|) =: ε_i`。
- 对 `q_p(s)` 到 `q_c(s)` 的关节直线应用 A1，再利用净空对点位移 1-Lipschitz，得到：
  `lb_c[k,g] ≥ lb_p[k,g] − Σ_i ρ[g,i] ε_i`（自碰撞对用 `pair_rho`）。
- 下界 > 0 则继承；否则对该段做 A2 认证。

**推论 A5（可靠，且不比从头认证更保守）**
- (i) Δ 接受 ⇒ 胶囊模型内整段无碰（A2 + A4）。
- (ii) Δ 拒绝 ⇒ 从头认证拒绝：被重新认证的段与从头认证使用同一认证器、同一深度，结果只取决于段端点；被继承的段不会导致拒绝。
- (iii) 反向不成立：某段从头认证在深度上限内返回 `unknown` 时，Δ 可能凭继承下界接受该段。这种接受仍然可靠。复核在 `max_depth=0` 下构造出了这种情形；试点（`max_depth=14`）中未观察到。

**推论 A6（批量等价）**：`inherit_batch` 对每个候选的判定与下界，等于逐个调用 `inherit` 的结果（测试 108/108 逐一相等）。

**备注：为什么离散采样做不到 D3。** 采样检查只给出采样点的净空，不给出整段下界，因此没有可以按关节偏差扣减的"余量"。它只有两个选择：每周期重新采样，或者接受无法证明的继承。这是 D3 与"把离散检查做快"的本质区别，也是 Δ-Cert-arm 必须建立在连续认证之上的理由。

### 3.3 链式租约流水线

**不变量 P1（链连续）**
- 任意时刻，已提交虚拟计划 = 第一张许可的起点 + 各许可前缀依次拼接。
- 每张链入许可的起点逐字节等于前一段的末端，其上下文绑定连续的 `queue_rev` 与已提交前缀的滚动摘要。

**不变量 P2（每次写入恰有一张已消费且仍有效的许可）**
- 每个队列条目都属于一张已原子消费的许可。
- 派发前检查该许可的代次、期限与剩余步完成预算。

**不变量 P3（撤销线性化）**
- 撤销与派发在同一把锁下互斥。
- 撤销在锁内推进代次并清空全部链入条目；此后任何 `tick` 看到 FAULT 状态都不再提交。
- 因此线性化点之后，旧代次新增提交为 0。这与基础执行器的不变量 4 相同，且覆盖所有链入许可。

**不变量 P4（逐步复核不减少）**
- 流水线下每一步写入前的复核集合 ⊇ 停走式下同一步的复核集合。
- 额外增加"相对已提交虚拟计划的跟踪管"检查。
- 队列状态比较对象是"最近一张已提交许可"。因为队首许可自身的 `queue_rev` 已被链上后来的许可取代，这是停走式"与当前许可比较"在流水线下的对应。

**命题 P5（吞吐）**
- 条件：控制器容量 ≥ 1、每周期至多派发一步，且 `max_ahead ≥ 1`、每周期能准备好下一张许可。
- K=1 时，H 步需要 `H + c` 个周期，c 为控制器回报延迟（参考控制器 c=1）。
- 停走式约需 `H·(1 + 排空延迟/K)` 个周期。
- 试点：40 步需 41 个周期；停走式在 K=1/2/4/8 时分别需 80/60/50/45 个周期。

## 6. 正式实验设计（冻结协议）

### 6.0 全局约定（所有 V 系列实验共用）

- **冻结**：投稿前固定 commit、随机种子表、Python/numpy/MuJoCo 版本、CPU 型号与频率策略（`performance` governor，`taskset` 绑核），写进 `experiments/registry/V*.json` 后再跑。登记后若修改协议，必须新开版本号并保留旧结果。
- **预注册**：每个实验的确认性假设、主指标与阈值，在跑之前写进登记文件；探索性分析单独标注。
- **计时**：
  - 用 `time.perf_counter_ns`；每格先跑 20 个预热周期，不计入。
  - 报告中位数、P95、P99。
  - 跨 ≥3 次独立进程重复。
  - 比值的 95% CI 用按重复分块的 bootstrap（10,000 次）。
- **比例**：用 Wilson 95% 区间。0/n 时上界约为 3.84/n（n=1000 时为 0.38%）。
- **配对**：同一种子生成的同一组计划同时交给所有方法；判定分歧逐例记录。
- **成本口径**（表述纪律）：
  - Δ 路径一律计入根证书建立、索引构建、失败回退、证书构造与哈希。
  - 基线若有未计时的准备工作（如 v1 Δ 每周期为平移父计划重建证书），必须注明偏向哪一方。
  - 同时报告函数调用次数（FK 次数、距离计算次数）与端到端墙钟。
- **多重比较**：确认性性能假设（H2b、H4b、H5a）用 Holm–Bonferroni 校正，α=0.05。
- **产物**：每次运行输出 JSON，含 schema、commit、环境、种子，以及原始逐周期记录的 SHA-256。仿照 `tools/check_results.py` 写核对脚本，把正文每个数字追溯到文件。负结果全部保留。

### 6.1 V1 契约故障矩阵（RQ3 扩展，对应 D1）

- **目的**：在随机化实例上比较各模式对契约故障的阻断能力，并测量干净运行的误拒。
- **自变量**：
  - 模式：{P0 仅记录（影子模式，作下界）, P1, P2, EVC v1, EVC v2, EVC v2 流水线}；
  - 故障类：本文 17 类 + 原生网关的证据缺口类；
  - 随机化因子：K∈{1,2,4}；控制器容量 {1,2,4}；ACK 延迟 {0,1,3} 周期；注入时刻（均匀落在提交前、派发中、撤销窗口）；种子；pre_revoke 类的卡顿时刻与恢复时刻。
- **"出厂"变体**：另跑一组"调用方不提供 `scene_hash` / 撤销时刻"的 EVC v2，量化 N11 的影响。
- **样本量**：每个"模式 × 故障类"组合 200 个随机实例；干净运行每种模式 1000 回合（数值剖面），外加原生网关 40 回合配对。
- **指标**：
  - 阻断率（Wilson CI）；
  - 越权写入次数（任何未授权的 `controller.submit`）；
  - 撤销后旧代次新增提交；
  - 干净运行误拒率；
  - 每次 commit/dispatch 守卫的额外耗时（µs，中位数与 P95）。
- **确认性假设 H1**：EVC v2 的两种执行器对全部故障类阻断 200/200，越权写入 0，干净运行误拒 0/1000。
- **原生部分**：
  - 在 SmolVLA/LIBERO 原生网关上复跑适用的类：动作替换、1 ulp、旧反馈、过期、重放、并发重放、证据缺口。
  - 沿用现有 40 回合配对网格。
  - 额外指标：成功回合数不变；授权与准入开销 P95 ≤ 现有 1.040 ms 的 1.1 倍。

### 6.2 V2 Δ-Cert v2 规模化（RQ2，对应 D2）

- **网格**：H ∈ {16, 40, 64, 128, 256} × M ∈ {1, 2, 3, 4, 8, 16, 32, 64, 128, 256} × jitter ∈ {0.0005, 0.001, 0.003, 0.01} × 变换 ∈ {流式平移+混合, 整体扰动, RTC 尾部, 修复}；每格 10 次重复 × 120 周期。
- **方法**：
  - v1 完整、v2 完整（索引）、v1 Δ、v2 Δ；
  - 另加**自适应**路径：按 M 与上一周期的回退率在 v2 Δ 与 v1 完整之间选择。这是对 N1 的工程回应，规则须预先固定，例如 M<4 直接完整检查。
- **指标**：
  - 每周期墙钟的中位数、P95、P99；
  - 距离计算次数；
  - 复用、继承、回退的段数；
  - 判定分歧；
  - 盈亏平衡面 M*(H, jitter)。
- **确认性假设**：
  - H2a：所有方法与 v1 完整检查的判定分歧为 0。
  - H2b：在 M≥16、jitter≤0.003 的全部格子中，v2 Δ（含根摊销）的墙钟中位数低于 min(v1 完整, v2 完整)，且比值 95% CI 下界 > 1。
  - H2c（预期为负，照常报告）：M=1 时 v2 Δ 不快于 v1 完整。
- **消融**：惰性路径关/开；active_k ∈ {0, 1, 2, 4}；far_cap ∈ {0.05, 0.10, 0.20}；ε ∈ {1e-12, 1e-9, 1e-6}；关闭偏移对应（强制完整）；关闭逐字节复用；关闭索引（线性扫描）。每项报告其对 H2b 格子加速比的影响。
- **W1 复测**：1000 个构造案例，父证书成本计入，照常报告 N2。

### 6.3 V3 机械臂连续认证准确性（RQ1 机械臂，对应 D3"更准"）

- **构造**：沿扫掠胶囊路径放置障碍，穿透深度分层 {0.05–0.1, 0.1–1, 1–5, 5–20 mm}，并对称构造等量的净空案例。净空候选的筛选规则与剔除数照常报告。
- **网格**：r_obs ∈ {0.055, 0.02, 0.008, 0.004} m × speed ∈ {1, 2, 4} × 深度层；每格 1000 个穿透 + 1000 个净空。
- **方法**：只查路点；离散 {0.05, 0.02, 0.01, 0.005, 0.002} rad；连续认证（max_depth 14 与 24）。
- **MuJoCo 交叉核对**（本沙箱没有 MuJoCo，需在有 MuJoCo 的环境运行）：
  - 每个被连续认证判为无碰的计划，用官方 MJCF 在 0.0005 rad 密采样上做 `mj_collision` 检查，期望 0 接触；
  - 每个判为碰撞的计划给出接触见证点；
  - 统计 `unknown`（深度耗尽）的比例。
- **确认性假设 H3**：
  - 连续认证对全部穿透案例漏检为 0（模型内保证），MuJoCo 交叉核对 0 接触；
  - 同时报告每种离散步长与"只查路点"的漏检率（Wilson CI），以及各方法的成本曲线（"准确性—成本"帕累托图）。

### 6.4 V4 机械臂流式与多候选（RQ2 机械臂，对应 D3"更快"）

- **网格**：N ∈ {1, 4, 8, 16, 32, 64, 128} × jitter ∈ {0.001, 0.002, 0.005, 0.01, 0.03} rad；60 个根 × 50 周期。
- **候选生成**（两种）：
  1. 平滑高斯扰动（本试点的做法）；
  2. **真实策略采样**：SmolVLA flow-matching 的 N 个噪声种子，或 SO100/LIBERO 回放中的块修订。
- **实现**：numpy（本试点）+ 编译内核（Numba 或 C++/Eigen，同一算法）。后者用于检验"FK 次数下降能否在 N=1 时兑现为墙钟"。
- **方法**：只查路点、离散 0.01、从头认证、Δ-arm；Δ 计入根证书摊销。
- **消融**：链感知 ρ vs 朴素 ρ（每个关节都按整臂最远距离计）；含/不含自碰撞对；tight ∈ {∞, 0.03}；max_depth ∈ {10, 14, 18}。
- **确认性假设**：
  - H4a：Δ-arm 接受 ⇒ 从头认证接受或 `unknown`；Δ-arm 拒绝 ⇒ 从头认证拒绝（推论 A5）。同时报告实际分歧数。
  - H4b：numpy 实现下，N≥8、jitter≤0.01 时，Δ-arm 墙钟中位数（含根摊销）比从头认证快，比值 95% CI 下界 > 1.5。
- **探索性问题**：编译内核下，N=1 的墙钟比值能否达到 FK 比值的一半以上。

### 6.5 V5 链式租约流水线（新 RQ：逐步授权的吞吐代价）

- **网格**：K ∈ {1, 2, 4, 8} × max_ahead ∈ {1, 2, 4} × 控制器容量 ∈ {1, 2, 4, 8} × 回报延迟 ∈ {0, 1, 2, 4} 周期；计划长度 40、200、10,000 步（后者检验长时间运行的开销）；每格 20 个随机种子（撤销时刻、反馈噪声）。
- **指标**：
  - 完成周期数、空闲周期数；
  - 授权年龄均值与最大值；
  - 每次提交的耗时随运行时长的变化；
  - 撤销后控制器已接受的前缀继续执行的步数（物理上不可撤回的部分，照常报告）；
  - 撤销后新增提交（必须为 0）；
  - 每步复核耗时。
- **确认性假设**：
  - H5a：流水线 K=1 的完成周期数 ≤ H + 回报延迟 + 1，且授权年龄最大值 ≤ 1 个 dt + 回报延迟。
  - H5b：所有格子、所有种子下，撤销后新增提交为 0。
- **原生部分**：在 SmolVLA/LIBERO 原生网关上以"流水线 + K=1"执行动作块，与现有配置配对 40 回合，比较成功回合数、逐字节一致率、每回合墙钟与许可开销。

### 6.6 V6 一体化闭环（规格书 X2，审稿必问）

- **链路**：策略提出动作块（或 N 个样本）→ Δ-Cert-arm → 流水线许可 → 原生写入器 → 证据。
  - Δ-Cert-arm 需要目标机器人的运动学模型。LIBERO 用的是 Panda，Menagerie 中有 `franka_emika_panda`，可用 `ur5e_kin` 的同一方法解析。
- **场景几何**：LIBERO 场景中的桌面与物体用保守的包围球或胶囊表示为障碍；记录"自然变换使旧证书失效"的频率。
- **指标**：
  - 自然失效率；
  - 每周期验证墙钟（中位数与 P95）；
  - 成功率与基线是否一致；
  - 门禁**真正改变发送动作**的次数：只有大于 0 才能说"闭环"，否则只能说"在线复核"。
- **状态**：[待做]。完成之前，论文只能说"机制在数值与运动学剖面上成立"。
