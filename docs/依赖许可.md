# 依赖许可登记

**这张表是本次环境实测**：在干净虚拟环境里执行 `python -m pip install -e ".[test]"`
之后，逐个读安装目录 `*.dist-info` 里的许可证声明（PEP 639 的 `License-Expression`
字段）与随包许可证文件得到的。**不是从上游文档或二手资料抄的。**

实测环境：Python 3.14.6 / Windows / 2026-09-19（与 `RESULTS.md` 同一轮）。

## 结论与边界

- 本项目自身许可是 **MIT**（见仓库根 `LICENSE`）。MIT 与上表中的 MIT / BSD / Apache-2.0
  没有兼容性冲突 —— 这些许可都比 MIT 宽松或相当，且都不是 copyleft。
- **双许可的包（cryptography、packaging）若要再分发，必须选定其中一份。** 本仓库
  只按依赖使用，不打包分发它们的代码，所以尚未做这个选择。
- 若将来把本项目打成 wheel/sdist 分发，**这张表必须由人再过一遍**，特别是：
  PyPI 上各包的许可声明可能随版本变化，本表只对上面写明的版本负责。
- 这条对应实施方案发布前检查清单的第 6 条：「依赖许可逐项登记，不用上游代码许可
  推断权重可再分发」。

## 复现这张表

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python - <<'PY'   # Windows 上请写成脚本文件再执行
import importlib.metadata as md
for d in sorted(md.distributions(), key=lambda x: x.metadata["Name"].lower()):
    print(d.metadata["Name"], d.version, d.metadata.get("License-Expression"))
PY
```
